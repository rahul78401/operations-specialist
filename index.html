Session 0

How the Internet Works

Everything in this guide runs on the internet. Here it is, one picture at a time.

1What is the internet?

A global system for passing data from one place to another. It is real equipment: cables, routers and servers.

2Rules and packets

Millions of different devices share one set of rules, TCP/IP. Big files travel as small packets.

3Client and server

The client asks. The server answers. Anyone with a device and a connection can reach a server.

4Frontend and backend

Every product has two parts: what you see, and what works behind it.

5API

The frontend and backend are far apart. The API lets them talk.

You will use APIs hands-on in Session 1.

6JSON

APIs send data as JSON: plain text that people and programs can both read.

7HTTP and HTTPS

HTTP is the set of rules for a request and a response. HTTPS is HTTP with encryption.

Remember

Always use HTTPS, especially for logins, payments and API keys.

The full picture

Practice

In your own words, explain what happens from the moment you open an Instagram profile on your phone until the profile appears. Use these words: client, server, frontend, backend, API, JSON, HTTPS.

Session 4

API Integrations and Webhooks

Products are made of several applications that exchange data. Learn how that exchange works and what happens when it fails.

What you will learn

  • How two different applications exchange data
  • API request and response lifecycle
  • Webhooks versus polling
  • JSON payload validation
  • Pagination when fetching large datasets
  • Duplicate requests and idempotency
  • Retry logic and handling failed integrations

Practice

Explain how a payment provider notifies your backend that a payment succeeded, and how you prevent processing the same event twice.

Session 5

Debugging and Troubleshooting

When something breaks, find where it broke before you change anything. Collect evidence, then act.

What you will learn

  • Reading application logs and stack traces
  • HTTP errors versus database errors
  • Reproducing bugs using Postman
  • Checking request IDs, timestamps and payloads
  • Understanding timeouts and slow queries
  • Separating frontend, backend and third-party API issues

Practice

An endpoint returns HTTP 500. Explain how you would investigate it step by step instead of immediately changing code.

Session 6

Security and Data Handling

You will have access to customer data. Learn who may do what, and how to keep secrets and personal data safe.

What you will learn

  • Authentication versus authorization
  • SQL injection and parameterized queries
  • API key and secret management
  • Input validation
  • Role-based access control
  • Personally identifiable information and safe logging

Practice

Explain how you would prevent an unauthorized user from accessing another customer's records.

Session 7

Git, Linux and Basic Tooling

Production issues are investigated from a terminal and a code repository. Learn the basics you need there.

What you will learn

  • Git branches, commits, merge conflicts and pull requests
  • Environment variables and configuration
  • Basic Linux commands: cd, ls, grep, tail
  • Reading logs and checking running processes
  • Environment differences between development and production

Practice

Trace a production issue from a log entry to the relevant endpoint and database query.
